- `POST /api/pairing/redeem` menerima hanya kode dan kunci publik perangkat beserta signature proof; tidak menerima ID/grants/peran klien. Kode acak 128 bit, default TTL 5 menit/maksimal 10 menit, hanya hash SHA-256 tersimpan. - Penebusan menggunakan satu transaksi Firestore: cek izin issuer/relasi/expiry/state, konsumsi kode, buat ID perangkat UUID server, binding kunci, credential/grants dan audit. Retry transaksi/race tidak membuat credential ganda atau hasil parsial. Revocation kode/perangkat juga transaksional; revocation kode yang sudah redeemed mengembalikan state sebenarnya, sedangkan pencabutan akses memakai endpoint perangkat. Riwayat tidak dihapus.
- Binding memakai kunci publik ECDSA P-256 SPKI. Request dengan credential pairing wajib menyertakan tanda tangan SHA-256/P1363 atas method, target lengkap, hash token/kode, hash body, timestamp dan nonce. Jendela waktu ±60 detik; nonce per perangkat tersimpan atomik dan dibatasi 120 entri aktif. Replay, token curian tanpa kunci, kunci salah, perubahan target/body, atau data binding rusak ditolak. Device dan credential memiliki marker `p256-v1`, sehingga kunci/marker hilang tidak menurunkan akses ke jalur bearer legacy. Kredensial legacy/in-memory tetap menggunakan perilaku sebelumnya.
- `GET /api/device/status` memerlukan credential + proof sah dan mengembalikan ID/state aktif/expiry/grants; akses expired/revoked ditolak 401.

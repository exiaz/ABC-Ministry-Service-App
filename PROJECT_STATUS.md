## M2B.2 — Device Pairing API

- Menggunakan Auth/Firestore Emulator dan guard admin M2B.1 yang sudah ada pada `demo-abc-attendance`; tidak mengubah frontend, adapter in-memory, konfigurasi Firebase/versi dependency, atau admission token admin. Tidak ada instalasi baru, login/pairing UI, operasi absensi, data nyata, cloud, billing, deployment, commit atau push.
- Endpoint admin: `POST /api/admin/pairing-codes`, `POST /api/admin/pairing-codes/{pairingId}/revoke`, `GET /api/admin/devices/{deviceId}`, `POST /api/admin/devices/{deviceId}/revoke`. Seluruhnya memerlukan token admin M2B.1 sah dan izin server tambahan pada `adminPairingPermissions/{uid}` di namespace Firestore. Dokumen `{active:true,grants:[{schoolId,groupId,serviceSessionId}]}` dikelola proses/operator server tepercaya; tidak ada endpoint untuk memberi izin tersebut. Cakupan harus cocok seluruh tuple sekolah/kelompok/pelayanan, tanpa wildcard. Izin yang hilang menolak secara default. Otorisasi admin diperiksa ulang setelah I/O sebelum commit tulis.
- `POST /api/pairing/redeem` menerima hanya kode dan kunci publik perangkat beserta signature proof; tidak menerima ID/grants/peran klien. Kode acak 128 bit, default TTL 5 menit/maksimal 10 menit, hanya hash SHA-256 tersimpan. Token perangkat tetap acak 256 bit dan hash sesuai mekanisme M2A.3, dengan grant default/maksimal 1 jam dari penebusan. Tidak mencatat kode/token mentah. JSON dibatasi 8192 byte; field/query/origin yang tidak didukung ditolak. Error kode tidak dikenal/expired/revoked/reused sama dan tanpa informasi sensitif.
- Penebusan menggunakan satu transaksi Firestore: cek izin issuer/relasi/expiry/state, konsumsi kode, buat ID perangkat UUID server, binding kunci, credential/grants dan audit. Retry transaksi/race tidak membuat credential ganda atau hasil parsial. Revocation kode/perangkat juga transaksional; revocation kode yang sudah redeemed mengembalikan state sebenarnya, sedangkan pencabutan akses memakai endpoint perangkat. Riwayat tidak dihapus.
- Binding memakai kunci publik ECDSA P-256 SPKI. Request dengan credential pairing wajib menyertakan tanda tangan SHA-256/P1363 atas method, target lengkap, hash token/kode, hash body, timestamp dan nonce. Jendela waktu ±60 detik; nonce per perangkat tersimpan atomik dan dibatasi 120 entri aktif. Replay, token curian tanpa kunci, kunci salah, perubahan target/body, atau data binding rusak ditolak. Device dan credential memiliki marker `p256-v1`, sehingga kunci/marker hilang tidak menurunkan akses ke jalur bearer legacy. Kredensial legacy/in-memory tetap menggunakan perilaku sebelumnya.
- `GET /api/device/status` memerlukan credential + proof sah dan mengembalikan ID/state aktif/expiry/grants; akses expired/revoked ditolak 401. Admin dengan seluruh cakupan dapat melihat status aktif/expired/revoked dan mencabut perangkat. State device, grant, kode habis, audit, nonce dan limiter persisten di Firestore; restart API nyata diuji. Tidak mengubah ID/absensi historis, snapshot, profil privat, penugasan mentor tetap maupun override sesi.
- Limiter persisten transaksional: 10 request redeem/menit per alamat socket (termasuk invalid), 20 operasi pairing admin/menit per UID; tidak percaya X-Forwarded-For atau ID pilihan klien. 429 memakai pesan aman dan `Retry-After: 60`. Limiter tetap menolak pada context backend baru. Di loopback, klien uji berbagi budget alamat lokal; brute-force juga dibatasi entropi kode. Tidak ada CORS, cookie/session baru atau resource cloud; mode/config emulator hilang/invalid menutup akses tanpa fallback.
